Ransomware detection refresh

Teaching page for the Riverbend Managed IT Services lab pack: twelve Wazuh rules on Sysmon and Windows events, plus what they miss. Riverbend, its hostnames, and sample accounts are fictitious. Incident TLDRs below are from public reporting on named real cases.

1. Kill chain 2. Three incidents 3. Rule cards 4. Interview lines 5. Self-quiz

A hiring-manager skim: open this page, read one incident, read one rule card, then run pytest -q in the repo. The pack is host telemetry (Sysmon EID 1/10/11/13 plus Security/System). It does not see a VPN or Citrix login. MFA failures are a control gap, not a Wazuh miss.

1. How modern ransomware chains unfold

Most 2021–2024 human-operated ransomware is not a smash-and-encrypt binary. Operators live in the network for hours to weeks. This lab maps that path onto twelve primary rules (100100–100111) and two support rules (100120 parent write, 100121 mass-write burst at level 15).

Initial access

Stolen VPN or Citrix passwords, unused portals left on, phishing, or a trusted RMM/update channel. This pack has no identity rule. The first host-visible step is often a download cradle or an encoded PowerShell stager.

100111 T1105 100110 T1059.001 Catch Invoke-WebRequest, iwr, Net.WebClient, certutil -urlcache, bitsadmin /transfer, curl.exe -o, and -enc / -EncodedCommand / -w hidden / -nop -ep bypass.

Precursor tooling

Operators drop remote admin tools, disable Defender, and clear logs so later stages are quieter. Persistence (run keys, scheduled tasks, odd services) often lands here so they survive a reboot.

100108 T1562.001 Defender / auditpol / Sysmon stop. 100109 T1070.001 Security 1102, System 104, wevtutil cl. 100105 T1547.001 Run/RunOnce to user/temp/script. 100106 T1053.005 schtasks /create /sc with a script host or \Users\. 100107 T1543.003 New service ImagePath in user/temp or a script host.

Credential theft

LSASS memory access is the usual path to domain-wide movement. Sysmon EID 10 with a dump-capable access mask is the lab’s SEV-1 signal.

100100 T1003.001 TargetImage ending in \lsass.exe and GrantedAccess in 0x1010, 0x1038, 0x1fffff, 0x143a.

Lateral movement

Admin shares and PsExec-style service installs turn one workstation into a file server or DC problem. Non-loopback 5140 on ADMIN$/C$ and a PSEXESVC 7045 are the two dedicated rules.

100103 T1021.002 100104 T1569.002 100107 also fires if they register a non-PsExec service from a user-writable path.

Shadow copy deletion

Inhibit recovery before encrypt. Classic: vssadmin delete shadows, wmic shadowcopy delete, bcdedit recovery off, wbadmin delete catalog, plus PowerShell WMI/CIM Win32_ShadowCopy removal (sibling 100122 on 4104).

100101 T1490 SEV-1 level 14. This is the last cheap chance to page before notes drop.

Encryption

Ransom-note names and double extensions on Sysmon EID 11. Level 15. Local firewall isolation. If they keep original names, the mass-write burst is the backup tripwire.

100102 T1486 notes / .locked .encrypted .crypt .enc. 100121 30 user-document writes in 60 seconds on the same computer (level 15, also isolates).

2. Three incident TLDRs (public reporting)

These are not Riverbend events. They are named, public cases. The “would catch” lines assume the same Sysmon plus Wazuh pack was on the Windows endpoints. They are not a claim that this lab was present.

Kaseya VSA / REvil (July 2021)

Attacker. REvil (Sodinokibi) ransomware operators. They used a vulnerability in Kaseya VSA, an RMM used by managed service providers, and rode the trusted update/agent channel into downstream customer endpoints over the US Independence Day weekend (CISA/FBI Kaseya VSA guidance, July 2021; Kaseya’s public incident updates).

Timeline.

  1. Operators obtain the ability to instruct VSA to run a payload on managed agents (supply-chain / RMM abuse, not a random workstation exploit).
  2. A malicious “update” lands on MSP customer endpoints from software the help desk already trusts.
  3. On-host ransomware behavior follows: inhibit recovery, encrypt files, drop ransom instructions. Public estimates of downstream impact started in the hundreds of businesses and were later refined; the precise count is less important than the fan-out through one RMM.
  4. Kaseya took VSA SaaS offline. A decryptor later became available after disruption of REvil infrastructure (public FBI/Kaseya statements).

What this lab’s rules would catch. On each Windows host that still had Sysmon: 100101 if they used watched VSS/bcdedit/wbadmin strings; 100102 on listed note names or .locked-style extensions; 100121 if they burst-wrote user documents; possibly 100110/100111 if a decoded PowerShell cradle was visible outside the VSA agent. Isolation would fire only on level 15 (100102/100121).

What went wrong. The delivery path looked like a legitimate RMM job. TC-07 in this repo treats rmm_agent running signed -File scripts from C:\Program Files\RMM\ as zero-alert on purpose. A Kaseya-style push that never shows -enc or a user-writable ImagePath will not page on 100110/100107. Independent endpoint detection (VSS delete, notes, mass writes) is the residual net. Customers who only trusted the MSP’s green dashboard had no second sensor.

Interview-ready sentence. “Kaseya 2021 is why I will not allowlist an entire RMM process tree: I allowlist the signed health-check pattern we regression-test in TC-07, and I still page on T1490 and T1486 because a trusted agent can still delete shadows and write ransom notes.”

Colonial Pipeline / DarkSide (May 2021)

Attacker. DarkSide ransomware (RaaS). Colonial Pipeline Company publicly described a compromise that began through a VPN account. The account had no MFA. Reporting and company statements described a legacy VPN that was still reachable.

Timeline.

  1. Stolen or reused VPN credentials, no MFA, unused portal still on the internet (company statements, May 2021).
  2. Operators spend on the order of a week inside IT: tooling, credential theft, and lateral movement typical of DarkSide affiliates (public technical reporting: remote admin, LSASS, SMB).
  3. 7 May 2021: encryption / discovery; Colonial shut down pipeline OT as a precaution because IT and OT were coupled enough that they would not risk running blind.
  4. Colonial paid a bitcoin ransom (about $4.4 million at the time). The US Department of Justice later recovered a large share of that bitcoin. East Coast fuel disruption followed the shutdown, not a unique encryptor trick.

What this lab’s rules would catch. Nothing on the VPN logon itself. Once on Windows: 100111/100110 for common stagers; 100100 for LSASS dump masks; 100103/100104 for admin-share and PSEXESVC; 100108/100109 if they killed Defender or cleared logs; 100101 before encrypt; 100102/100121 at encryption time. That is a precursor page, not a pipeline-control system.

What went wrong. Identity: an unused VPN without MFA. Architecture: IT compromise was treated as an OT stop because the company could not prove isolation. Detection that only watches the OT historian would have been silent. Host Sysmon on the jump path is the relevant sensor for this pack.

Interview-ready sentence. “Colonial is an MFA and asset-inventory failure first: this Sysmon pack would not have seen the VPN bind, but it is built to page on LSASS, ADMIN$, and vssadmin so the week of hands-on-keyboard is not a silent week.”

Change Healthcare / ALPHV-BlackCat (February 2024)

Attacker. ALPHV (BlackCat) ransomware operators / affiliates. Change Healthcare (UnitedHealth Group) is a claims clearinghouse. Public congressional testimony described a Citrix remote-access portal that did not have MFA, used with a compromised credential. Some later technical write-ups also discussed Citrix session-token theft (CVE-2023-4966, “Citrix Bleed”) as a method used against Citrix in that era; the company’s testimony emphasized the portal and the missing MFA.

Timeline.

  1. Remote access to a Citrix portal without MFA (public testimony, 2024).
  2. Hands-on-keyboard in Windows: data theft plus ransomware, consistent with ALPHV affiliate playbooks (exfil then encrypt).
  3. 21 February 2024: Change Healthcare systems taken offline; pharmacy claims and payments failed at national scale for days to weeks.
  4. UnitedHealth later stated a ransom was paid (public reporting around $22 million). Disruption cost and PHI exposure dominated the aftermath, not the encryptor’s file extension.

What this lab’s rules would catch. Not the Citrix logon. On domain-joined Windows that had this Sysmon config: the same precursor set as Colonial (100100, 100103, 100104, 100110, 100111, 100108), then 100101 and 100102/100121. BlackCat often uses legitimate admin channels; renamed PsExec cousins and WMI without PSEXESVC are documented misses for 100104.

What went wrong. MFA was not on a remote-access concentrator that sat in front of a system the US health-payment system depends on. Concentration risk is a business-architecture issue. This pack does not fix that. It only shortens the dwell once a Windows host starts dumping LSASS or deleting shadows.

Interview-ready sentence. “Change Healthcare 2024 is why I separate identity detections from host detections: I will say out loud that rules 100100–100111 never see a Citrix bind, and I will still insist on T1003.001 and T1490 because those are the Windows steps that turn a portal foothold into a clearinghouse outage.”

3. Per-rule cards

False-positive handling is not a comment in the XML. It is TC-07: synthetic benign events that must produce expect.rule_id: null. test_tc07_zero_alerts fails the pack if any primary rule matches them.

100100 · T1003.001 · LSASS memory access · SEV-1 · level 14

Catches. Sysmon EID 10 (parent 61612) when TargetImage is lsass.exe and GrantedAccess is a dump-capable mask (0x1010, 0x1038, 0x1fffff, 0x143a). TC-03: procdump-style and full-access samples.

Misses. MiniDumpWriteDump from a trusted signed process; other masks (including some query-only opens).

False positives / TC-07. Defender MsMpEng.exe opening LSASS with 0x1400 (defender_lsass.json). That mask is not in the allow-list of dump masks, so the rule stays quiet without an exclusion on the Defender path.

100101 · T1490 · Shadow copy deletion · SEV-1 · level 14

Catches. Sysmon EID 1 (parent 61603): vssadmin delete shadows, wmic shadowcopy delete, vssadmin resize shadowstorage, bcdedit /set {default} recoveryenabled no, wbadmin delete catalog, plus PowerShell WMI/CIM Win32_ShadowCopy removal. Sibling 100122 covers 4104 script blocks. TC-01 v1/v2/v3.

Misses. Renamed vssadmin/wmic, diskshadow.exe, compiled WMI with no watched strings. Query-only Get-WmiObject Win32_ShadowCopy without Remove-*/Delete() is out of scope.

False positives / TC-07. Backup account svc_backup running vssadmin list shadows and wbadmin start backup (backup_agent.json). The regex keys on delete/resize/catalog-wipe, not list or start backup.

100102 · T1486 · Ransom note / encryption artifact · SEV-1 · level 15 (AR)

Catches. Sysmon EID 11 (parent 61613) on note names (RANSOM_NOTE.txt, README_TO_DECRYPT, HOW_TO_RECOVER, DECRYPT_INSTRUCTIONS) or double extensions .locked, .encrypted, .crypt, .enc. TC-06. Active response: local firewall isolate.

Misses. Encrypt-in-place that keeps original names. Custom note filenames (html/hta/operator-chosen) not on the list.

False positives / TC-07. Word writing quarterly-notes.docx (normal_document_write.json) is a 100120-class user-path write at most, not 100102. Burst isolation is 100121 (30/60s), not a single Office save.

100103 · T1021.002 · SMB admin-share · SEV-2 · level 12

Catches. Security 5140 (parent 60100) with ShareName ADMIN$ or C$ and a non-loopback IpAddress. TC-04.

Misses. IPC$-only, 5145-only, or 5140 never logged because share audit is off.

False positives / TC-07. Loopback 127.0.0.1 / ::1 ADMIN$ (loopback_admin_share.json) is ignored on purpose so local admin tools do not page.

100104 · T1569.002 · PsExec-style service · SEV-2 · level 12

Catches. System 7045 (parent 60001): service name PSEXESVC, ImagePath %SystemRoot%\PSEXESVC.exe, or ImagePath under \\ADMIN$\. TC-04.

Misses. Renamed service, Impacket smbexec/wmiexec with no PSEXESVC, PAExec/CSExec.

False positives / TC-07. Software deploy creating RiverbendDeploy with ImagePath under C:\Program Files\Deploy\ (software_deploy.json) is not PSEXESVC and is not 100107 either.

100105 · T1547.001 · Run / RunOnce · SEV-2 · level 12

Catches. Sysmon EID 13 (parent 61615) on \CurrentVersion\Run\ or \RunOnce\ when Details point at \Users\, \Temp\, \AppData\, \ProgramData\, or a script host. TC-08.

Misses. COM hijack, Winlogon, IFEO; Run keys whose Details are signed Program Files binaries.

False positives / TC-07. Run key Details C:\Program Files\Riverbend\agent.exe (runkey_programfiles.json) does not match the user/temp/script Details regex.

100106 · T1053.005 · Scheduled task · SEV-2 · level 12

Catches. Security 4698 or Sysmon EID 1 schtasks /create with /sc and a script host or \Users\ path. TC-09.

Misses. Task Scheduler COM / Register-ScheduledTask with no schtasks /create /sc on the command line. Signed Program Files actions.

False positives / TC-07. No scheduled-task sample in TC-07; the closest cousin is RMM running -File from Program Files, which never includes schtasks /create.

100107 · T1543.003 · Suspicious new service · SEV-2 · level 12

Catches. System 7045 ImagePath under \Users\, \Temp\, \AppData\, \ProgramData\, or containing powershell, cmd.exe /c, rundll32, -enc. TC-10. PSEXESVC belongs to 100104.

Misses. LOLBin ImagePath under System32; MSI install into Program Files.

False positives / TC-07. Same software_deploy.json Program Files ImagePath. Windows Update (wuauclt, usoclient, TiWorker) is EID 1, not 7045.

100108 · T1562.001 · Defender or logging disabled · SEV-2 · level 13

Catches. Set-MpPreference -Disable*, Add-MpPreference -ExclusionPath, Defender DisableAntiSpyware / DisableRealtimeMonitoring set to 1, auditpol /clear, Stop-Service -Name Sysmon. TC-11.

Misses. GPO/WMI tamper, sc stop WinDefend, fltmc unload without those strings.

False positives / TC-07. Windows Update processes do not carry those command lines (windows_update.json). Backup and RMM samples likewise do not disable Defender.

100109 · T1070.001 · Event log cleared · SEV-2 · level 13

Catches. Security 1102, System 104, Sysmon EID 1 wevtutil cl / Clear-EventLog. TC-02.

Misses. .NET EventLog.Clear from a compiled binary, odd quoting, copied binary name, Security 1100 (service shutdown).

False positives / TC-07. wevtutil qe Security (query, not cl) in wevtutil_query.json. The matcher is clear/cl, not query.

100110 · T1059.001 · Encoded / obfuscated PowerShell · SEV-3 · level 10

Catches. Sysmon EID 1 and PowerShell 4104: -enc, -e , -EncodedCommand, FromBase64String, -w hidden, -nop -ep bypass. Daily queue, not a page. TC-05.

Misses. Token splitting, GZip+IEX, many Invoke-Obfuscation variants that never use those markers.

False positives / TC-07. RMM powershell.exe -File C:\Program Files\RMM\health.ps1 and -ExecutionPolicy Bypass -File from that same tree (rmm_health.json). Bypass plus a signed Program Files -File is not -enc and is not -w hidden.

100111 · T1105 · Download cradle · SEV-3 · level 10

Catches. Invoke-WebRequest, iwr , DownloadString, DownloadFile, Net.WebClient, certutil -urlcache, bitsadmin /transfer, curl.exe -o, Start-BitsTransfer. TC-12.

Misses. Invoke-RestMethod, browser downloads, local certutil -decode, split-PID transfer.

False positives / TC-07. RMM health scripts do not include those transfer strings. Windows Update uses its own agents (wuauclt/usoclient/TiWorker), not certutil urlcache.

4. Ten interview-ready sentences

  1. This pack pages on precursors (LSASS, shadow-copy delete, admin shares) so encryption is not the first alert.
  2. Active response is a local Windows firewall isolate, bound only to level 15 (100102 and 100121), with a documented manual rollback and no timeout.
  3. TC-07 is the false-positive contract: Windows Update, backup VSS list / start backup, signed RMM -File under Program Files, Defender LSASS 0x1400, loopback ADMIN$, Program Files services and Run keys, wevtutil qe, and a normal Office save.
  4. Rule 100102 misses encryptors that keep original names; 100121 is the burst backup, not a substitute for a note matcher.
  5. I confirm stock parent SIDs with wazuh-logtest on the deployed Wazuh build because 61603/61612/60100 drift between releases.
  6. Kaseya 2021 is why an RMM allowlist is a pattern (signed Program Files health script), not a blank check on the agent process tree.
  7. Colonial and Change Healthcare are MFA-on-remote-access failures; these twelve rules never see the VPN or Citrix bind.
  8. 100104 is PSEXESVC on purpose; Impacket without that service name is a listed miss, not an untested hope.
  9. SEV-3 (100110, 100111) is a same-day queue at level 10 so encoded PowerShell does not hide a SEV-1 page and does not wake the on-call by itself.
  10. Isolation is not process kill: DNS, SMB, and AD die until isolate-host.ps1 -Rollback; a wrong manager IP in extra_args can leave only a hypervisor console.

5. Self-quiz

Open a row only after you have an answer. These are the questions a reviewer should be able to fail you on.

1. Which two rule IDs can trigger host isolation, and why not 100101?

100102 and 100121 only. Isolation is bound to Wazuh level 15. 100101 is SEV-1 but level 14 (page, do not auto-isolate), because backup mistakes on VSS delete should not brick the host’s DNS/SMB without a human.

2. Why does vssadmin list shadows under svc_backup not fire 100101?

The matcher is delete/resize/catalog-wipe (and PowerShell Remove/Delete on Win32_ShadowCopy), not list. TC-07 backup_agent.json is the regression that keeps that distinction.

3. Name one LSASS access that is supposed to be silent.

Defender MsMpEng.exe with GrantedAccess 0x1400. Dump masks in 100100 are a tight set. Direct syscalls still produce Event ID 10; they only miss when the mask is outside the set.

4. Would this pack have alerted on the Colonial VPN logon or the Change Healthcare Citrix portal?

No. There is no identity/MFA rule. Alerts start when Windows host telemetry matches (LSASS, ADMIN$, encoded PowerShell, VSS delete, notes).

5. What is the Kaseya lesson for TC-07’s rmm_agent samples?

Signed -File health scripts from C:\Program Files\RMM\ stay zero-alert so real RMM does not melt the queue. A VSA-style malicious push is still expected to show up on T1490/T1486/100121 if those behaviors happen. Do not widen the allowlist to “any child of the RMM agent.”

6. 100104 vs 100107: who owns a new service?

PSEXESVC / ADMIN$ ImagePath is 100104. User/temp/script-host ImagePath is 100107. A Program Files MSI service is neither (TC-07 software deploy).

7. Where do level 10 alerts go, and which rules are they?

Daily triage queue, not paging. 100110 (encoded PowerShell) and 100111 (download cradle). Routing is in the coverage map: SEV-3 = level 10–11.

8. What does 100102 miss that 100121 is meant to backstop?

Encryption that keeps original filenames and extensions, or notes with custom names. 100121 fires on 30 user-document EID 11 writes in 60 seconds on the same computer (parent 100120), level 15.

9. How do you prove a rule change did not break benign traffic?

Add or keep a TC-07 JSON with expect.rule_id: null, run pytest -q, and refuse to ship if test_tc07_zero_alerts fails. Tuning.md says the same: a live exclude that still matches the primary regex is not done.

10. Parent SID 61603 stopped matching after a Wazuh upgrade. What first?

Confirm the stock parent with /var/ossec/bin/wazuh-logtest on that build before rewriting field regexes. Coverage-map calls this out: IDs drift.
